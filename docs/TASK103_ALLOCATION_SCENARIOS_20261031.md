## 1. 원본 #103 계약과 근거

160원장 #103: **“강사 보수·플랫폼 수수료·소개 보상의 재원과 분담을 숫자 사례로 계산한다.”** 이 문서는 정책 결정이나 지급 시스템이 아니라 해당 **숫자 사례**를 분리하여 검증한다. `phase3/team14_referral_eligibility.py::eligible_referral`는 실제 조상 수혜자 후보만 반환하는 **모의 산식**이다. `phase3/team14_referral_scenarios.py::simulate_referral`는 조상 존재 여부를 반영하지 않는 **추상 예산 배분**이다. 둘을 혼동하지 않는다.

다음 수수료 20%(2,000bps), 직접 소개 3%(300bps), 2단계 소개 1%(100bps)는 **기존 테스트용 가정**이다. 강사 보수는 `floor(총액 × (10,000 − 수수료bps − 전체 예정 소개bps) / 10,000)`로 계산하며, 각 **실제 존재하는** 조상에게 `floor(총액 × 해당 bps / 10,000)`을 배분한다. 플랫폼 잔액은 `총액 − 강사 보수 − 실제 조상 보상액 합`이다. 존재하지 않는 상위 조상의 미배분액과 정수 나눗셈 잔여는 플랫폼 잔액에 남는다.

**주의:** B에서 2단계 조상이 없더라도 이 **현재 테스트 산식**은 강사 보수를 76,000원으로 유지한다. 미배분 1,000원은 플랫폼 잔액으로 남는다. 이를 실제 계약상 플랫폼의 확정 수익이나 강사 몫이라고 해석하면 안 된다. 10단계는 코드 상한일 뿐 운영 승인 단계가 아니다.

- 가상 총액 101원, 수수료 2,000bps, 소개 333bps+167bps, 실제 조상 2명: 강사 **75원**, 직접 **3원**, 2단계 **1원**, 플랫폼 **22원**. 합계 **101원**. 정수 절사 잔여는 플랫폼에 남는다.
