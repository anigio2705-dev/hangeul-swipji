# 한글쉽지 6팀 재귀형 자율 조직 실행 지시 — 2026-10-29

## 대표의 조직 원칙
중앙 HQ가 모든 일을 직접 하지 않는다. 11~16 각 팀은 독립된 **팀 총괄 AI**가 되고, 자기 책임의 160개 계약 부분집합을 하위 전문 역할로 분해한다. 각 팀 총괄은 작업 계획·하위 배정·독립 QA·실패 재작업·다음 작업 승계·증거 보고를 책임진다. 중앙 HQ는 팀 간 의존성, 충돌, 통합, 최종 승인 경계를 관리한다. 하위 조직은 역할 정의일 뿐 실제 AI 호출·독립 실행이 확인되기 전에는 '작동 중인 에이전트'로 세지 않는다.

## 공통 하위 조직 모델
각 팀 총괄 아래 (A) 탐색·설계 담당 (B) 실제 구현 담당 (C) 독립 테스트·반례 담당 (D) 실패 분석·수정 담당 (E) 다음 작업 큐·증거 담당을 둔다. 한 번의 AI 호출이 다섯 역할을 서술만 한 경우는 독립 병렬 실행으로 인정하지 않는다. 초기에는 기존 GitHub Actions의 승인된 실행 비용·호출 제한을 지키면서 실제 분리된 호출/커밋/검증 증거를 단계적으로 만든다.

## 실제 실행 프로토콜
1. 팀 총괄은 매 주기 전체 자기 소유 과제를 읽고 우선순위 3개와 실행 가능한 다음 1개를 선정한다.
2. 하위 탐색 담당이 실제 파일·테스트·의존성·수락 조건을 확인한다. READY=0이면 이 단계의 실제 산출물을 만들고 독립 QA에 보낸다.
3. 하위 구현 담당은 승인된 READY에서만 격리 브랜치에 코드를 작성한다. 수정 파일·AI 호출 ID·SHA를 기록한다.
4. 다른 하위 검증 담당이 독립 테스트와 반례를 수행한다. 실패하면 수정 담당에 재작업을 보내고 같은 테스트로 재검증한다.
5. 팀 총괄은 통과/실패를 판정하고 다음 번호를 선택한다. 팀 간 의존성이 생기면 중앙 HQ에 소유권·파일 충돌 요청을 등록한다.
6. 중앙 HQ는 6개 팀 총괄의 증거를 통합하고 코드 검증/실사용 검증/대표 승인 단계를 분리한다. AI가 스스로 OWNER_APPROVED를 부여할 수 없다.

## 1시간 실험 평가
팀별 실제 하위 역할 호출 수, 독립 AI 호출 수, 코드 diff, 신규 고유 검증 과제, 실패-수정 사이클, 다음 과제 승계, 사람 개입, 비용을 측정한다. 팀별 총괄이 단지 계획 문서를 쓴 경우는 FAIL/NOT PROVEN으로 보고한다. 초기 AGI 실험은 계층적 자율 계획·협업·전이 능력의 측정이지 AGI 구현 증명이 아니다.

## 안전·자원 제한
승인된 격리 브랜치, 최소 권한, 기존 호출 상한, 파일 소유권, CI 비용 제한을 유지한다. 무제한 자기복제·무제한 하위 에이전트 생성·운영 배포·main 변경·운영 DB·실결제·외부 제출은 금지한다. 실제 하위 AI 호출을 늘리는 것은 독립 테스트와 비용/권한 확인 후 단계적으로 승인한다.
