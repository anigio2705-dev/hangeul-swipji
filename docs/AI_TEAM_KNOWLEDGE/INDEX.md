# 6팀 공동 지식 저장소 — 실증 사례 색인

대표 명령 제16~18조에 따라 각 팀은 실패·성공·재사용의 **증거와 범위**를 분리해 기록한다. 이 파일은 격리 통합 브랜치에서 만든 초기 구조이며 전체 팀 운영 배포를 뜻하지 않는다.

## 디렉터리
- [성공 사례](SUCCESS/README.md): 제품 수정·테스트·통합·배포를 각각 별도 판정
- [실패 사례](FAILURE/README.md): 재현 조건, 원인 가설, 기각된 방법, 다음 시도
- [공통 교훈](LESSONS/README.md): 적용 조건·금지 조건·회귀 검사
- [팀 간 적용](CROSS_TEAM/README.md): 다른 팀의 적용 실험과 실제 결과

## 최초 실증 사례
- [13팀 통합 CI 원본 감사 실패](FAILURE/TEAM13-20261030-ORIGINAL-AUDIT.md) — 13팀 회귀 성공과 전체 통합 실패를 구분; 12·15팀 협력 요청

## 사례 작성 필수 필드
사례 번호 / 팀 / 160개 과제 번호(미확정 시 미확정) / 증상·재현 / 최초 시도 / 결과 / 근본 원인(검증 여부) / 수정 파일·SHA / 테스트·독립 검증 / 다른 팀 교훈 / 적용 금지 조건 / 관련 팀·후속 작업.

## 상태 분리
CODE_CHANGED / UNIT_PASS / INDEPENDENT_PASS / INTEGRATION_PASS / STAGING_DEPLOYED / USER_FLOW_VERIFIED. 하나가 성공해도 뒤 단계의 성공을 추정하지 않는다.

## 재사용 절차
새 과제 선택 → 사례 색인 조회 → 현재 환경과 적용 조건 비교 → 실제 변경 및 테스트 → CROSS_TEAM에 적용 결과 연결 → 독립 검증 → 원사례와 교훈 갱신. 15팀은 증거 없는 성공 판정을 거부한다.

## 개선 지표
신규 성공·실패 건수, 교차 재사용 건수, 재사용 후 테스트 성공 건수, 동일 장애 재발, 해결 시간, 다음 과제 자동 승계율. 실제 측정치가 없으면 '미측정'으로 기록한다.
