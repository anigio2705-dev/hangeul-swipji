# AI TEAM KNOWLEDGE — 공동 경험 저장소

대표 추가 실행 명령 제16~18조의 격리 브랜치 시범 구현. **이 파일의 생성은 전 팀 도입 또는 자동화 완료의 증거가 아니다.**

## 디렉터리
- [SUCCESS](SUCCESS/README.md): 검증 단계별 성공 사례
- [FAILURE](FAILURE/README.md): 실패·원인·반례
- [LESSONS](LESSONS/README.md): 반복 검증된 재사용 원칙
- [CROSS_TEAM](CROSS_TEAM/README.md): 다른 팀의 적용과 재검증 결과

## 공통 사례 양식
- 사례 번호 / 작성 팀 / 160개 과제 번호
- 문제 및 재현 절차 / 최초 시도 / 성공·실패
- 근본 원인(증거·가설 구분) / 실제 수정 방법
- 변경 파일·커밋 SHA·PR·CI URL
- 자체 테스트 / 독립 감사 / 통합 / 테스트99 배포 각각의 상태
- 재사용 교훈 / 적용 금지 조건 / 협력 팀 / 다음 작업

## 작업 시작 전 필수 확인
1. 이 색인과 SUCCESS/FAILURE/LESSONS에서 동일 오류·환경·작업 번호를 검색한다.
2. 재사용 가능한 사례의 적용 조건을 비교한다.
3. 수정과 테스트를 실제 수행하고 SHA·CI로 증명한다.
4. 적용 결과를 CROSS_TEAM에 연결한다.
5. 15팀 독립 감사 전에는 '독립 검증 완료'라고 표시하지 않는다.

## 상태 정의
CODE_CHANGED / TEST_PASS / INDEPENDENT_PASS / INTEGRATION_PASS / DEPLOYED_VERIFIED / FAILED / BLOCKED. 각 상태는 별개이며 자동 승격하지 않는다.

## 운영 원칙
기존 기록 삭제 금지. 관련 사례는 링크로 연결. 팀별 성공·실패·재사용 건수, 재발 건수, 해결 소요시간, 승계 성공률을 실행 로그 기반으로 산출하며 임의 수치를 기록하지 않는다.
