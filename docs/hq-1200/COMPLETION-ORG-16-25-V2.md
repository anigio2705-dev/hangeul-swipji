## 고정 회차가 아닌 6개 통과 게이트
**G0 원본/현황 확정**: 25팀이 원본 800·600·160의 실제 원문과 출처를 확보해 중복 연결. 16~23팀이 GitHub 실제 파일·함수·콘텐츠와 연결. 미확인은 미확인으로 남긴다.
**G1 안전한 통합 기반**: 16·24팀이 배포 SHA, Render99 DB 백업/복원, CI, 인증, 권한을 확인. 실제 서버 무단 배포 금지.
**G2 무료 교육 전수 완성**: 17·18·23팀이 350/1758/439/600/8언어 전수 검증하고 오류 수정.
**G3 유료 수업 전수 완성**: 19·20팀이 유료 커리큘럼 모델·전체 수업 수를 근거로 확정 후 강사용·학생용 전체 자료와 LMS 연결. 시범 8개로 완료 금지.
**G4 화상·거래·운영 완성**: 21·22·20·23팀이 매칭→화상→수업 이벤트→정산/환불→관리자 확인 E2E. 기존 정상 자동매칭 보존.
**G5 실제 서버 인수**: 24팀이 실제 배포 SHA·PC/모바일·서로 다른 2기기·관리자·백업 복구·회귀 테스트를 확인, 25팀이 원본 ID 누락 0 증명, 총괄 검토 후 대표 공개 출시 승인.

## 업무 관리 규칙
- **작업 개수/회차 상한 없음**. 각 작업은 source_id, unique_work_id, owner, actual_path, function_or_content_id, dependency, test_case, evidence, deployed_sha, status를 가진다.
- 원본 800은 감사 건수이지 확정 버그 수가 아니다. 600/160과 단순 합산하거나 원본 ID를 덮어쓰지 않는다.
- 팀은 코드 존재만으로 완료 처리할 수 없다. 24팀은 독립 검증, 25팀은 누락 감사, 총괄은 회차 인수, 대표는 사업·출시 최종 승인.
- 결제 실운영, 개인정보 처리, 강사 보수·세금·환불 약관 등은 관련 법률/계약/운영 승인을 별도 종료 조건으로 관리.
- 테스트 서버와 기존 GitHub 정상 기능 보존; 실제 배포는 백업·권한·승인 확보 후 실행.
- 완료 보장은 사전 선언이 아니라 위 종료 조건이 실제 증거로 모두 충족되었을 때만 판정한다.

## 첫 실행 명령
25팀: 원본 800/600/160 출처와 고유 ID 목록 확정. 16~23팀: 담당 코드·콘텐츠의 실제 경로/함수/ID를 원본과 연결하고 필수 E2E 목록 제출. 24팀: 배포/백업 위험 및 수용테스트 목록 확정. 결과를 바탕으로 개별 작업 수와 우선순위를 산정한다.
