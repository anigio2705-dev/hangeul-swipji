# 한글쉽지 160개 과제 전수 개발 계약 초안 — 원본 대조형

생성 기준: `automation/hq_backlog_160.md` 원문 160개 항목. 이 문서는 원본 요구사항을 보존한 **1차 전수 계약**이다. 파일·테스트 경로와 단일 담당이 확인되지 않은 과제를 개발 가능하다고 거짓 표시하지 않는다.

## 개발 계약 필수 관문
1. 과제 번호·원문 목표·수정 파일·담당팀·선행 과제·자동 검사·반례·승인 기준을 매핑한다.
2. 실제 코드 검색과 독립 의미 검증을 거쳐서만 `READY` 전환. 잘못된 파일/과제 매핑은 즉시 `BLOCKED`.
3. `READY→RUNNING→CODE_VERIFIED→PUBLIC_VERIFIED→OWNER_APPROVED`와 `BLOCKED/FAILED`를 구분한다. 기존 기능은 증거 검사 후 인정한다.
4. 실패 로그→원인→재현 테스트→수정→독립 재검증→후속 작업 배정의 폐회로를 실행한다. 동일 실패 무한 반복 금지.
5. 실제 결제, 운영 DB, main, 공개 배포, 외부 제출/연락은 명시 승인 없이 변경하지 않는다.
6. 11~16팀 병렬화는 파일 소유권·의존성·안전 검사 통과 시만 허용한다. 15팀 독립 감사를 개발자 자기평가와 구분한다.
7. 개발시간·CI 시간·홈페이지 실사용 검수 시간을 분리하고, 검증된 기능 수를 보고한다.

## 2026-10-31 — 대표 최종 READY 1 방식 복원 (Issue #34 최신 명령)

- **중앙 총괄본부:** 과제 선정·배정뿐 아니라 격리 코드/문서 직접 수정, 정확 SHA READBACK, CI 실행·로그 확인, 실패 원인 재작업, 최종 내부 READY 판정의 단일 책임자. 중앙 자신의 개발과 최종 검증은 한 조직의 증거이며 **두 개의 독립 승인표가 아니다**.
- **15팀:** 중앙과 다른 실제 실행에서 정확 SHA 독립 QA_PASS/FAIL. 새 SHA/실질 변경 없으면 이미 검증한 #102 문서 PR #156의 477 tests·14 반례를 중복 실행하지 않는다. QA_FAIL이면 중앙이 원인·반례를 수정하고 새 SHA로 다시 QA를 요청한다.
- **무인개발팀:** 중앙의 GitHub 쓰기·Actions 기동·코드 실행·환경 장애를 복구하는 지원 역할. 별도 DEV_PASS 승인표는 요구하지 않으며 정상 중앙 개발에 중복 개입하지 않는다.
- **내부 판정:** 중앙 실제 수정·실행/CI 증거 + 15팀 독립 QA PASS + 중앙 최종 검증을 충족해야 INTERNAL_READY=1. 문서 비교의 기술 QA 통과는 보상 정책 승인/운영 지급 승인이 아니다. #102 PR #156의 §5 정책 미결정 게이트는 별도로 남으며, 이를 3역할 강제 게이트로 혼동하지 않는다.
- **보호:** 같은 GitHub 계정 댓글은 독립 GitHub APPROVED가 아님. main/운영 DB/TEST99 재배포/실결제·실지급 금지. 이벤트 큐는 현재 영속 워커가 아닌 메모리 파일럿. 160개 계약 행은 그대로 보존.
