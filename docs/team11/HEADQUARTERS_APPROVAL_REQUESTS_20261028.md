## 요청 11-HQ-001 — GitHub Actions 실행 증빙 확보
- 부서명: 11 공통 기반·계약팀
- 요청 내용: 총괄본부 권한으로 team11/common-foundation-20261028 브랜치의 `.github/workflows/team11-contract-tests.yml` 실행 가능 여부 확인, 실제 checkout SHA·실행 URL·종료 코드·통과/실패 수 확보. Actions 정책/권한이 막히면 원인을 확인하여 본부에 기록.
- 필요한 이유: 기존 21개 통과는 총괄본부 확인사항이며 5차 신규 어댑터 10개 포함 31개 테스트의 실제 GitHub Actions 결과는 11팀이 아직 확보하지 못함.
- 위험: CI 미실행 상태에서 호환성 PASS를 잘못 선언할 수 있음. 권한/설정 변경은 다른 워크플로에 영향을 줄 수 있으므로 최소권한 원칙 적용.
- 승인하지 않을 경우 영향: 신규 10개 검증과 5차 최종 완료 판정 HOLD. 기존 개발 및 독립 문서 검토는 계속 가능.
- 권장안: 총괄본부가 기존 workflow의 수동 실행 또는 브랜치 push 실행을 검증하고, Actions 로그와 SHA를 회수. 불필요한 권한 확대·운영 배포 금지.
- 상태: HOLD — 총괄본부 실행 증빙 대기.

## 요청 11-HQ-002 — 13·14팀 공통 계약 채택 및 연동 범위
- 부서명: 11 공통 기반·계약팀
- 요청 내용: 13팀 매칭의 users.role/approved, 매칭 응답·저장 상태와 14팀 월 과정의 month_id/lesson_index/booking_id/transaction_id·KRW 통화·오류 매핑에 대한 공통 어댑터 인터페이스 승인. 타 팀 코드 수정은 해당 팀과 총괄본부의 별도 지시를 통해 진행.
- 필요한 이유: 11팀 `phase3/common_compat_adapter.py`는 독립 순수 함수이며 13/14 운영 경로에 연결되어 있지 않음. 다중 역할은 기존 단일 역할 DB로 저장할 수 없음.
- 위험: 암묵적 역할 부여, 미승인 강사 권한 상승, 예약·월 과정 회차 오연결, 통화/정산 오류, 기존 자동 매칭 회귀.
- 승인하지 않을 경우 영향: 기존 서비스 보존, 신규 공통 계약의 실제 통합만 HOLD. 11팀 독립 테스트 및 호환성 점검 계속.
- 권장안: 단일 역할 read-only projection과 승인 상태 fail-closed를 유지하고, 13/14 팀장이 필드·상태 매핑과 마이그레이션 없는 연결 계획을 제출한 뒤 총괄본부가 기술 계약을 확정.
- 상태: HOLD — 본부 계약 승인 대기.
