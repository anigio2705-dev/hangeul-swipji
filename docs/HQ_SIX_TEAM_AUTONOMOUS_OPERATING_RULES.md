# 한글쉽지 총괄본부 — 6팀 160개 자동 개발 운영 규칙

## 목표와 권한
대표가 승인한 160개 실행표의 범위에서 총괄본부가 11~16팀을 지휘한다. 각 번호별 기존 구현을 먼저 검사하고 미완료 조건만 개발한다. 승인된 격리 브랜치와 팀 브랜치만 변경한다. main, 운영 DB, 실결제, 운영 배포는 절대 변경하지 않는다.

## 여섯 팀
- 11 공통 기반: 인증, 계정, 공통 인프라
- 12 교육: 350단원, 학습 진도, 발음·음원
- 13 플랫폼: 자동 매칭, 화상 수업, 수업 이벤트
- 14 사업: 추천, 보상, 환불, 모의 정산
- 15 품질·운영: 독립 회귀 테스트, 통합 CI, 실패 원인 분석
- 16 글로벌 성장: 다국어, 크리에이터·마케팅 기능

## 반복 실행 순환
1. 시작 즉시 최신 격리 브랜치 커밋·CI·160개 번호별 상태를 읽는다.
2. 우선순위가 높은 안전한 미완료 번호를 선정하고 의존성/파일 충돌을 검사한다. 독립 번호는 병렬 배정할 수 있으나 같은 파일의 쓰기 담당은 하나로 제한한다.
3. 팀별로 작업 번호, 완료 조건, 허용 파일, 테스트, 금지 행위, 결과 제출 형식을 명령한다.
4. 각 팀은 기존 코드 확인 → 최소 수정 → 단위/회귀 테스트 → 격리 브랜치 커밋 → CI 증거를 제출한다.
5. 총괄은 코드 diff, 테스트 결과, CI, 기능별 완료 기준을 확인해 PASS / RETRY / BLOCKED / FAIL을 판정한다. CI 성공만으로 전체 번호를 완료 처리하지 않는다.
6. PASS는 근거 SHA·CI·완료 기준을 번호에 연결하고 다음 미완료 번호를 즉시 선정한다. RETRY는 실패 로그와 원인을 지정해 제한적으로 재시도하고, 반복 실패 시 독립 작업으로 전환한다. BLOCKED는 승인·외부 자원만 대기시킨다.
7. 같은 실행에서 허용된 시간·비용 내 위 순환을 반복한다. 실행 종료 후에는 예약 실행기가 최신 상태를 읽어 이어받는다. 채팅이 종료되어도 무한 실행된다고 주장하지 않는다.

## 필수 상태 기록
번호 | 담당팀 | 우선순위 | 상태(미착수/개발중/재시험/외부대기/코드검증/최종완료) | 완료 조건 | 코드 SHA | CI URL | 재작업 횟수 | 다음 명령. 실행마다 변경 기능 수, 성공 CI 수, 최종 완료 번호 수, 소요 시간, 비용 확인 가능 여부를 기록한다.

## 음원 처리
매 실행 필수 음원과 실제 파일을 대조하여 ready/held/missing 및 경로·재생·권리 오류를 구분한다. 허가 없는 제3자 음원 복제와 합성 음성을 사람 녹음으로 속이는 행위를 금지한다. 외부 녹음 대기 중에도 다른 독립 개발을 계속한다.

## 자동화의 전제
이 문서는 운영 규칙이며, 실제 무인 재지시·스케줄·AI 개발 실행기 설치 및 통과를 증명하지 않는다. GitHub Actions schedule은 기본 브랜치 제약과 실행 지연이 있을 수 있으므로 격리 브랜치의 자동 실행 경로를 별도로 검증해야 한다.
