# 한글쉽지 격리 복사본 구동·코드 검토

대표님 지시: 현재 한글쉽지를 별도 시험 환경에 복사하여 실제 구동하고, 코드·기능·기록 보존을 검사한다.

## 기준과 판정

기준 소스는 제품 저장소 PR344 head `94a40b84c4c5665b5964b47f128b9472cfdae6eb`이다. main `fe9759fd0f60f20e784fae1d3d95625b63db1d93`보다 누적 자동 개발이 포함된 후보이며, 실제 홈페이지에 배포된 버전과 동일하다고 가정하지 않는다. 기존 AGENTS.md, GLOBAL_MASTER_PLAN.md, DEVELOPMENT_STATUS.md 및 교육 기준5문서를 읽었다.

**실제 Python/SQLite 서버와 API는 별도 임시 DB에서 구동했다. 브라우저 화면·전체 사용자 동선까지의 합격은 미완료다.** 이 창의 Chromium은 UNIX socket 생성 권한 문제로 시작하지 못했고, 제공된 UI 브라우저도 이 명령 환경의 loopback 서버에 연결하지 못했다. 이 환경 문제를 제품 오류나 제품 통과로 계산하지 않았다.

## 환경

- 기존 저장소를 새 로컬 checkout에 clone하고 기준 SHA를 detached checkout했다. 기존 코드와 저장된 작업 환경을 재사용하지 않았다.
- SQLite는 전부 생성한 임시 시험 DB이며 실제 회원·예약·운영 DB를 복사하지 않았다.
- Python 표준 라이브러리 서버를 loopback에서 실행했다. 확인용 HTTP 서버·자식 프로세스는 검사 마지막에 종료했다.
- npm은 phase3/package-lock.json의 기존 개발 도구만 설치했다. 새 서비스·유료 자원·모델 호출·운영 배포 없음.
- source 317개 blob을 대조했으며 제품 실행 코드·HTML·학습 콘텐츠 변경 없음. 변경은 기존 검사5파일과 신규 검사1파일, 문서·증거뿐이다. 감사 프로그램이 만든 결과는 이 보고서에 복사하고 기존 audit/phase2-content.json은 원문으로 되돌렸다.
- 이 복사본에서 ABCD/AS 엔진을 새로 돌린 것은 아니다. 자동화가 만든 제품 후보를 직접 검사한 것이다. 현재 운영 중인 별도24시간 시험과 독립이다.

## 최초 실패와 수정한 검사 자료

원본 Python 전체는89개 검사에서 failures4/errors4였다. 오류는4개 subtest 관측이며 별도의4개 test method로 중복 집계하지 않는다. 모든 최초 로그를 보존했다.

1. test_q002_timezone_server.py: 자체 구성한 과거 최소 DB에 session_observations 테이블과 audit.id가 빠졌다. 제품 init_db()에는 해당 스키마가 있다. fixture에 실제 초기화 함수 및 audit PK를 추가했다. 현재 응답에 새로 추가된 lateSeconds도 계산값을 명시적으로 검증하며 기존 필드/UTC/저장 불변 확인을 유지했다.
2. test_server.py/test_security.py: 기존 환불·재수업 검사가 새 상대방 진술 요건을 빠뜨렸다. 먼저 미진술409를 확인하고 상대방 계정으로 실제 진술 API를 호출한 뒤 기존 결과를 검증한다. 기존 ‘중복환불409’ 가정은 현재의 명시적 멱등 응답200/duplicate=true 계약으로 바꾸고 원장 행 수·합계 불변을 유지했다. 별도 신규 HTTP 검사에서도 검증했다. 서버의 승인·진술 요건은 낮추지 않았다.
3. check-foundations.cjs: 교육 데이터/음원 유틸리티를 실행하는 DOM 대역에 getElementById가 없어 최신 hangul-core.js의 UI 존재 확인에서 TypeError가 발생했다. 화면 없는 대역에 null 반환을 추가했다.350/1758,399조합,7일40문항,음원78파일의 원래 단언은 유지했다.
4. test_q002_timezone_ui.cjs: 최신 프로필 GET /api/me, 휴무 조회, 관리자 provider 페이지 API와 예약 참여자 시간대 응답을 모의 API가 제공하지 않았다. 모형 응답·호출 목록을 현재 인터페이스에 맞췄다. DST/UTC/참여자 시간대의 기존 기대값은 유지했다.

첫 수정 중 빠진 audit.id 및 lateSeconds 단언, 한 번의 검사 파일 들여쓰기 오류도 원인 조사 과정에서 드러났다. 중간 로그와 최종 로그를 구분했다. 성공하도록 제품 동작이나 검사 목표를 삭제하지 않았다.

## 화면 검사에 남은 조건

실제 브라우저로 다음을 완료해야 전체 구동을 수락할 수 있다.
- PC/390px에서 동일 기존 홈·무료 과정·읽기·언어·음원·진도 저장/재진입.
- 학습자/강사/관리자 세션을 분리하여 신청→프로필→승인→일정→예약→모의 결제.
- 과제/피드백/진단, 상대방 진술·관리자 결정·멱등 환불, 실제 두 참여자 일정 표시.
- 화면의 성공 문구와 API 재조회/DB 원문이 일치하는지, 다른 계정이 결과를 볼 수 없는지.

현재 확인 가능한 결론은 ‘별도 복사본의 서버·핵심API·기록 보존은 작동하고, 오래된 회귀검사 자료를 보완했다’이다. “전부 그대로 구동·무결점·화면까지 완료”로 보고하지 않는다. 브라우저 도구가 가능한 별도 승인된 시험 환경으로 동일 소스·검사 묶음을 옮기면 남은 검사를 이어갈 수 있다.

## 재현

저장소 루트에서:
```sh
npm ci --prefix phase3 --ignore-scripts
python reports/isolated-runtime-20261117/run_checks.py
```

이 실행은 일부 기존 감사 출력 파일을 생성할 수 있으며 운영 자료를 사용하지 않는다. check_local_runtime.py는 disposable localhost 서버를 같은 명령의 네트워크 공간에서 시작/확인/종료한다. 첫 별도 명령간 loopback 접속 시도는 연결 거부였지만 같은 명령의 서버·클라이언트 검사는 통과했다. 그 최초 실패는 http-pages.json에 보존하며 제품36페이지 오류라는 뜻이 아니다.

브라우저 최초 오류: browser-launch-error.txt. CUA 브라우저의 로컬 URL 오류는 GUI_BROWSER_CONNECTION.txt. 원본/수정전후 전체 결과는 같은 디렉터리 로그다.
